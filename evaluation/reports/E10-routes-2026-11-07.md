### (2) Findings

**MUST:** none.

**SHOULD**
- **SHOULD-1:** `apps/gateway/src/credassure/gateway/routers/cases.py:278`. The comment says the upload is refused "before reading", but FastAPI parses the whole multipart body (`await request.form()`, `fastapi/routing.py:455`) before any dependency runs. So an unauthenticated caller can make the server buffer a body of any size to disk before getting a 401 or 413; the per-IP rate limit caps how often, not how big. Fix: a small ASGI middleware on `/v1/cases/*/files` that returns 413 when Content-Length is over `max_upload_bytes + 64 KiB` and stops reading a chunked body once it passes the limit.
- **SHOULD-2:** `openapi.json` (built by `apps/gateway/src/credassure/gateway/openapi.py`) does not match runtime behaviour. The 24 agent-router operations have no `security` entry, because `agents/*/api/deps.py:17` `get_principal` has no HTTPBearer, and the gateway override is not reflected in the spec. No operation documents 401/403/404/409/413/415/429. 422 is advertised as `application/json` `HTTPValidationError`, but the API actually returns problem+json. The generated TS client and Schemathesis (#51) will be wrong. Fix: add `dependencies=[Security(HTTPBearer())]` (or openapi_extra security) when mounting agent routers, and pass a shared `responses={4xx: {"content": {"application/problem+json": {schema: Problem}}}}` to every router.
- **SHOULD-3:** `apps/gateway/src/credassure/gateway/routers/cases.py:410` calls `reads.verify_chain(s)` (`ledger/reads.py:61`), which walks every tenant's audit rows. A case audit response therefore returns other tenants' broken seq numbers, and tampering in tenant B shows `chain_ok=false` to tenant A. Fix: return only `chain_ok` and broken seqs filtered to `who.tenant_id`, or add a tenant-filtered verify.

**NIT**
- **NIT-1:** `agents/supervisor/src/credassure/agents/supervisor/api/router.py:48-51`. The retry stub has no evaluator role check, which scope #25 requires. Fix: add the role check now, so 9x cannot ship without it.
- **NIT-2:** `agents/copilot/src/credassure/agents/copilot/api/router.py:35`. The body is an untyped `dict[str, str]` checked by hand. Fix: reuse the `Chat` model from `routers/cases.py:347` so the schema matches the core chat route.
- **NIT-3:** `packages/observability/src/credassure/observability/log.py:36`. The redactor has no pattern for JWT, Bearer tokens or API keys. Nothing logs them today, so this is defence in depth. Fix: add `eyJ[\w-]+\.[\w-]+\.[\w-]+` and `(?i)bearer\s+\S+` patterns.
- **NIT-4:** The 501 stubs (critic findings, lendwise offers/negotiate, working-capital cash-table, supervisor retry) skip the visibility check. They return the same 501 for every case_id, so nothing leaks now. Fix: when implementing them in Phase 9, route them through `SupervisorService` (`visible_case`), like `result` and `plan`.

**Known and already tracked (not counted as new):**
- Approver comments are stored unredacted until Phase 6 (`routers/workflow.py:229`).
- The per-team rate limit (NFR-04) is deferred; only per-user/IP limits exist (`main.py:132-170`).
- `/v1/health/ready` exposes token usage by spec (`routers/health.py:32`).

### (3) Verdict: **READY**

Every attack on the E10 list was refused: own-case approval, director on a VP case, cross-preparer and cross-tenant reads, 3 MB upload, XLSX, malformed CSV. Every protected route has a role check and returns 404 for cases the caller can't see, and all errors at runtime are RFC 9457. bandit, pip-audit and the `.env` check are clean, and the audit log is append-only with a hash chain that verifies.

Three highest-impact fixes:
1. **SHOULD-1:** refuse oversized upload bodies in middleware, before multipart parsing and auth.
2. **SHOULD-2:** make openapi.json declare bearer security on the agent routers and problem+json for all error responses, before #51 Schemathesis and the TS client depend on it.
3. **SHOULD-3:** scope the audit-chain verification in `/cases/{id}/audit` to the caller's tenant.
