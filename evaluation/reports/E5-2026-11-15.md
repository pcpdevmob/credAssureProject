## 2. Findings

### MUST
None.

### SHOULD
1. **Fixed after this run (interim guard `BANNED` + passed-rule check, `test_VER03_*`).** `agents/onboarding/src/credassure/agents/onboarding/agent.py` `_explain`: a model reply that names every failed id but also says "Decision: GO, approved" is used as the narrative. The gate is unaffected (NO_GO), but the text contradicts it and predicts approval (VER-03).
   - Fix: until 9d wires `verify_claims`, reject replies that contain `GO`, `approv`, `accept`, `cleared` or `sign`, or any rule id that passed, and use the template instead.
2. **Recheck mismatch blocker code:** a ledger disagreement is reported as `SUP_SCHEMA_INVALID` (`agent.py` `make_recheck`; the default recheck in `graph.py` does the same).
   - Fix: add `SUP_RECHECK_MISMATCH` to the blocker catalogue. This is not an `AgentResult` change.
3. **Live latency:** on local qwen3:8b one call took 17–65 s, and one call hit the 30 s limit (ADR 0008). The agent now falls back to the template on `LLMError` (`test_ONB04_model_timeout_keeps_the_code_gate_and_uses_the_template`).
   - Fix: measure on the course endpoint before G2. If p95 is over 30 s, set `LLM_MAX_TOKENS` low for `onb_explain`.

### NIT
1. **Missing employee record:** reuses `ONB_TRAINING_MISSING` (`field="hr_profile"`). A dedicated code would read better in the UI.
2. **`tools/registry.py` `_load()`** re-reads `registry.yaml` on every ledger access. Fix: cache it once per process.
3. **`_GuardedLedger._ledger`** is reachable by attribute access, so this is a convention, not a sandbox. Record it in the threat model.

## 3. Verdict: **READY**

**Highest-impact fixes:**
1. Add an interim banned-wording guard on the `onb_explain` reply (SHOULD 1), then replace it with `verify_claims` in 9d.
2. Add `SUP_RECHECK_MISMATCH` so overrides read correctly in the audit and the UI (SHOULD 2).
3. Measure `onb_explain` latency on the course endpoint and tune `LLM_MAX_TOKENS` (SHOULD 3).
