### (2) Findings

**MUST**
- M1 `packages/llm/src/credassure/llm/client.py:17`: model calls are not traced. When this real adapter runs, there is no model span. **Fix:** wrap `complete()` in `span("llm", name=name, model=self._model, trace_id=…)` that records tokens and latency, or wrap the port in a gateway-side tracing decorator so FakeLLM paths are covered as well.
- M2 `packages/tools/src/credassure/tools/runner.py:31`: tool calls are not traced or audited, which design-detail §2.3 requires. Phases 9a–9e will register handlers here, so the gap opens the moment tools go live. **Fix:** wrap the call body in `span("tool", agent=self.agent, tool=name, case_id=case_id, attempt=…)` and give the runner a `trace_id` from `StageContext`.

**SHOULD**
- S1 `agents/supervisor/src/credassure/agents/supervisor/graph.py:138`: the `sup_plan` model call runs before `span("plan")` at 145 opens. If it raises, it is never traced. **Fix:** open the span first and call the model inside it (M1's model span then nests under it).
- S2 `apps/gateway/src/credassure/gateway/supervisor_service.py:79`: `GET /v1/agents/supervisor/cases/{id}/plan` calls `supervisor.plan(case.id)` with no `trace_id`. Under `PLANNER_MODE=llm_proposes`, a read-only GET therefore spends model tokens, and its span becomes an orphan trace. **Fix:** serve the last stored Plan, or pass a request trace_id and skip the model on GET.
- S3 `packages/observability/src/credassure/observability/tracing.py:30-33`: the exporter fires at span entry and ends the observation immediately. Durations and errors are lost, which ARCH §8.8 RED and latency metrics need. **Fix:** export after `yield` in a `try/finally` with start/end time and error status.
- S4 `.importlinter` (contract `agents-via-supervisor`): it does not stop an agent `api/` module importing its own `agent.py`. **Fix:** add a `forbidden` contract from `credassure.agents.*.api` to `credassure.agents.*.agent` (or `layers` api → nothing in the agent internals).

**NIT**
- N1 `apps/gateway/src/credassure/gateway/supervisor_service.py:91`: the placeholder chat mints a random `trace_id` that matches no exported span. **Fix:** emit `span("chat", trace_id=…)`, or return `null` until Phase 9e.
- N2 `apps/gateway/src/credassure/gateway/routers/workflow.py:20` and `deps.py:15` import the concrete `Supervisor` and `NoPendingApproval` from `agents.supervisor.graph`. This is acceptable in the composition root, but routers could depend on `SupervisorPort` and a core error type instead. **Fix:** move `NoPendingApproval` to `credassure.core.errors`.

### (3) Verdict: NOT READY

Every structural boundary holds:
- lint-imports passes 8/8.
- There are no router → agent calls, no agent → agent calls, no OpenAI import outside `packages/llm`, and no ledger writes outside `SqlLedger`.
- Retrieval is N/A until Phase 7.

What fails is the E11 rule that every model and tool call carries a Langfuse span. The 3 highest-impact fixes:
1. **M1:** add a model span in `llm/client.py:17` (or a tracing `LLMPort` wrapper) carrying prompt name, model, tokens and trace_id.
2. **M2:** add a tool span plus an audit event in `tools/runner.py:31`, threading `trace_id` from `StageContext`. Do this before Phase 9 registers handlers.
3. **S1 + S3:** move the `sup_plan` call inside the plan span (`graph.py:138` vs `145`) and make spans export on exit with duration and error status.
