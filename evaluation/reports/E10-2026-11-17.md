## (2) Findings

- **SHOULD** — `apps/gateway/tests/test_phase10_contract.py` (fuzz fixture): the fuzz runs with a preparer token only, so approver and evaluator routes (decision, delete, audit, retry) mostly return 403. **Fix:** parametrize the token over preparer, director and evaluator; move `negative_data_rejection` to a nightly job.
- **NIT** — `apps/gateway/src/credassure/gateway/main.py` CORS `allow_methods=["GET","POST"]`: a browser `DELETE /v1/cases/{id}` would fail preflight (no web delete UI today). **Fix:** add `"DELETE"` when the evaluator UI gets a delete button.
- **NIT** — `apps/gateway/src/credassure/gateway/settings.py:89` `approval_threshold_paise` is read nowhere; routing and step-up both use `engines.routing.THRESHOLD`. **Fix:** remove the setting or pass it to both.
- **NIT** — `apps/gateway/src/credassure/gateway/routers/workflow.py` `_step_up`: `limiter.test` then `limiter.hit` is not atomic (parallel requests can exceed 5/min by the threadpool size). **Fix:** gate on `hit` in the failure path.

## (3) Verdict: **READY**

All 21 checks pass and nothing is at MUST level. The three highest-impact fixes:
1. Fuzz as director and evaluator too, so the decision, delete and retry routes are exercised past the 403.
2. One threshold source (remove `approval_threshold_paise` or wire it into routing and step-up).
3. Add `DELETE` to the CORS methods before any web delete control ships.
