## (2) Findings

**MUST**
- M1 — KR-05 recall@5 is 26/40, 8 short of the 34 target (`evaluation/reports/retrieval-2026-11-15.md`, headline). Fix: widen `relevant_doc_ids`/`relevant_sections` by pooled top-10 judgement, done by a non-copilot owner and blind to which configuration retrieved each passage (E8-2026-11-14 SHOULD 1). Misses at document level are often a different relevant document ranked higher. Labels must not be fitted to the results.

**SHOULD**
- S1 — The KFS case-isolation filter is only exercised by unit tests, because all 111 case-scoped KFS have `effective_from` 2026-11-16, after AS_OF 2026-11-15, and no retrieval query carries a `case_id`. The date filter removes them before the case filter is reached. Fix: the owner decision already in PROGRESS.md (date the KFS on or before AS_OF in v2, or exempt case-scoped documents from the date filter by ADR), then add 2 case-scoped queries in a v2 query set.
- S2 — Coverage of distractor kinds is thin: other_state has 2 documents (R-STATE-003 IN-UP, R-STATE-006 IN-KA), and every query uses `lender_type=commercial_bank`. Fix: in v2 queries, add one NBFC-lender query so the `applies_to` filter is tested in both directions.
- S3 — On the larger corpus, dense without rerank is the weakest retriever (17/40 on fixed512 and section). The reranker lifts section/dense from 17 to 26. Fix: re-decide `RERANKER=none` (ADR 0013) after S1/M1. Hybrid without rerank (25) is 1 query below the best, so the default is still defensible.

**NIT**
- N1 — `semantic/hybrid/rerank` also reaches 26/40, but the report names only section/dense as best. Fix: list ties in the headline.
